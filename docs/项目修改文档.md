# 嵌入式系统学习 AGENT — 项目修改文档

本文档用于：**视觉与交互原则**、**管理员功能说明**、**知识库维护约定**，以及 **当前待解决的界面与产品问题（需求摘录）**。具体代码实现以仓库为准；历史实现细节不逐条堆叠在本页。

---

## 一、视觉与交互原则（简洁优先）

- **工程感、可读性优先**：中性灰白或克制深色底，留白充足；避免大面积渐变与高饱和蓝/紫/品红主色。
- **主色**：单一低饱和点缀色即可，与主题配置统一，不做多层渐变。
- **后续迭代**：主题变量（`.streamlit/config.toml`）、全局静态 CSS（`ui_style.py`）、`login.py` / `webui.py` 布局与组件选用，均须符合以上原则。

---

## 二、管理员侧栏：仅保留「已实现」的调试项

以下四项在 **`webui.py`** 中实现，并与助手消息展示绑定；**不应再增加「未接线」的调试开关**。

| 侧栏文案（与代码一致） | 变量名 | 作用 |
|------------------------|--------|------|
| 显示术语命中 | `show_ent` | 展示 glossary 对问句的术语命中。 |
| 显示意图 | `show_int` | 展示意图识别结果。 |
| 显示拼装上下文 | `show_prompt` | 展示发往大模型的完整上下文文本。 |
| 显示轻量图谱源码 | `show_graph` | 展示由 `related_ids` / `prerequisite_ids` 生成的 Mermaid **源码**（非实时渲染图）。 |

**说明**：普通用户与管理员在历史消息中「知识点关联」展开逻辑，以代码为准；若产品上要改为「仅管理员可见 Mermaid 源码」，需同时改代码并更新本段。

## 三、知识库与数据目录（`data/embedded`）

| 文件 | 说明 |
|------|------|
| `embedded_kb.json` | 主知识库：`id`、`title`、`tags`、`platform`、`body`、`source`、`related_ids`、`prerequisite_ids`；供检索与 Mermaid 子图。 |

修改数据后刷新页面；缓存异常时可重启 Streamlit。

## 四、界面与侧栏待优化（需求摘录）

> 本节为 **后续改界面时的需求清单**，摘自当前使用反馈；**实施时以本节为准逐项对照**，并可在完成后删减或勾选。

### 4.0 登录 / 注册页（当前实现说明）

与 **`static-ui/auth.html`** 及 **`login.py`** 对齐，当前约定如下：

- **无左侧栏**：未登录时不使用侧栏选择模式；通过 CSS 隐藏 Streamlit 侧栏占位，主区占满宽度。
- **右上角切换**：顶栏（主区顶部）左侧为产品标题与一句说明，**右侧为「登录」「注册」两个按钮**切换模式（`st.session_state.auth_mode`：`login` / `register`）。
- **表单整页居中**：用户名、密码与提交按钮置于 **中间窄列**（列比例约 `[1, 1.35, 1]`），视觉居中。
- **字号**：表单内输入框、标签与提交按钮通过 **注入 CSS** 略大于 Streamlit 默认，便于阅读。
- **登录后主界面**：仍使用 **`webui.py`** 侧栏 + 对话区布局；本节其余条目主要针对 **会话页**，不再要求改动登录注册结构。

静态稿修改：编辑 **`static-ui/auth.html`** 与 **`static-ui/assets/auth.css`**（顶栏 **`align-items: center`**，使标题区与「登录 / 注册」按钮 **垂直中线对齐**）。

### 4.8 主对话区（DeepSeek 风格与会话列表，当前实现说明）

与 **`webui.py`**、**`ui_style.py`**、**`static-ui/chat-user.html` / `chat-admin.html`**、**`static-ui/assets/chat.css`** 对齐，约定如下：

- **登录后正文字号**：主对话区 Markdown 段落、列表等通过全局 CSS **略大于默认**（约 `1.08rem`），代码块略小以保证等宽密度；主容器 **略加宽**（大屏约 `58rem`）。
- **左右对话**：产品目标为 **用户 / 助手气泡分列两侧**（类似 DeepSeek）。Streamlit 原生 `st.chat_message` 已自带左右区分；若需进一步像素级对齐，可仅在 **`ui_style.py`** 中用 CSS 谨慎覆盖（避免破坏内置 flex）。
- **侧栏左上**：固定展示 **产品标题**、**一句能力说明**；其下 **`st.empty()` 占位**在侧栏控件渲染结束后写入 **「当前平台侧重」「当前模型」** 两行（与下拉/输入框选项一致）。
- **「当前窗口」改为会话列表**：侧栏使用 **固定高度可滚动容器**（`st.container(height=…, border=True, key="conv_list")`）内 **逐条 `st.button`** 模拟 ChatGPT / DeepSeek 左栏会话行：左对齐文案、圆角、当前会话 **primary** 高亮、其余 **secondary**；完整标题过长时 **截断显示**，**`help` 悬停**可看全文。
- **侧栏滚动策略**：**侧栏整体不出现纵向滚动条**（`ui_style.py` 对 `[data-testid="stSidebar"]` 设 `overflow-y: hidden`，并缩小标题/caption/控件区字号与行距、收紧分割线间距）；**仅「往期对话」容器内部**保留 `overflow-y: auto` 与固定高度，会话多时 **只在会话列表内滚动**。
- **会话标题**：`st.session_state.chat_titles` 与对话列同步；**首条用户提问前**标题为「新对话」等占位；**该会话内首条用户消息发出后**，若标题仍为占位规则，则 **自动用首问前若干字生成标题**（截断加省略号）；否则保留用户已有标题。
- **侧栏左下（账户区）**：使用 **`st.popover("👤 用户名")`**，**点击展开**后展示欢迎语两行说明 + **「返回登录」**（Streamlit 无可靠「纯悬停」组件，静态 HTML 稿用 CSS `:hover` 示意差异）。
- **其它**：主区 **不再重复**顶栏大标题与平台/模型（已迁至侧栏左上）；侧栏 **不展示**实现层路径与 Neo4j 等文案（与 4.5 一致）。

静态稿修改：编辑 **`static-ui/assets/chat.css`** 与 **`chat-user.html` / `chat-admin.html`**。

### 4.1 整体观感与布局（主应用会话页）

- **登录 / 注册页**已按 **4.0** 调整结构；若仍有细节问题可在 4.0 下追加子条。
- **主对话区**已按 **4.8** 调整一版；若需继续精修气泡或侧栏比例，可在 4.1 / 4.7 下追加。
- **左右分布不均衡**：主内容区与侧栏的视觉权重、对齐与留白需再调，避免「一侧挤、一侧空」或主区过窄的感受。

### 4.2 装饰与图片

- **无必要则不留图**：若 Logo 等图片对品牌或操作无实质帮助，可移除，避免占位、加载与版心干扰。

### 4.3 欢迎与身份文案排版

- 当前类似 **「欢迎，用户 112233 · 本地知识库 + 通义/DeepSeek」** 的一行长句，可读性一般。
- **期望**：通过换行、层级（如用户名一行、能力说明一行）、字重或字号区分，使欢迎区 **更符合常规产品排版**、一眼能扫读。

### 4.4 字体与间距

- **字号、行距、区块间距**调到符合 **常见桌面端阅读舒适区**（勿过小导致费眼，勿过大导致松散）；与 Streamlit 默认相比可做全局或分区微调（仍以静态 CSS / 主题为主）。

### 4.5 侧栏「数据与退出」类文案（产品向）

- 用户对 **「数据与退出」** 与 **「知识库：data/embedded/ · 不依赖 Neo4j」** 一段 **不理解其意义**，且 **不希望向终端用户强调未使用或实现层概念**。
- **期望**：
  - 侧栏 **只保留对用户有操作或认知价值** 的文案（如模型、平台、退出登录等）。
  - **不要**在面向用户的界面中强调 **Neo4j**（本项目未使用图数据库，与使用者无关）。
  - 若需给开发者看路径或架构说明，可放到 **README / 内部文档**，而非侧栏常驻。

### 4.6 侧栏尽量不滚动

- **目标**：在常见分辨率（如 1080p 高度）下，左侧 **尽量一屏展示完毕、少纵向滚动**。
- **手段方向**（实施时择用）：压缩小节间距、合并说明、次要信息收入 `expander`、减少重复 caption、控件默认折叠等。

### 4.7 左右栏比例与侧栏宽度

- 当前 **侧栏偏宽**，主对话区相对 **可展示宽度不足**。
- **期望**：**收窄侧栏**（在 Streamlit 允许的范围内用主题 / 全局 CSS 控制 `stSidebar` 宽度或最大宽度），使 **主区与侧栏比例更合理**；具体像素或比例可在实现时定一版设计值并回归常见窗口宽度。
