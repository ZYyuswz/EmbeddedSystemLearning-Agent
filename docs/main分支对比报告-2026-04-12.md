# LLM 自主实现能力接入报告（对比 main，2026-04-12）

## 1. 报告目标

你的目标是让系统支持这样一种工作模式：

- 你对 LLM 说一个功能需求
- LLM 自动完成设备扫描与板卡识别
- LLM 自动同步并分析官方资料
- LLM 自动生成或修改代码
- LLM 自动执行验证并给出结果

本报告围绕上述目标，给出当前分支相对 main 的可复用能力、关键缺口、当前风险与分阶段落地方案。

## 3. 面向你的目标，当前缺口是什么

### 3.1 缺少 LLM 任务编排器（核心缺口）

当前没有一个统一的 Agent Orchestrator 来做：

- 解析你的自然语言需求
- 拆解为步骤（识别板卡、同步资料、改代码、跑测试）
- 按依赖顺序调用工具
- 处理失败重试与回滚
- 输出完整可审计执行报告

### 3.2 缺少“代码修改闭环”能力

目前虽有项目生成与命令执行，但没有形成完整闭环：

- 代码定位与编辑策略（文件级、方法级）
- 修改后自动 lint/test
- 失败自动修复再验证
- 结果归档与变更摘要自动生成

### 3.3 资料同步仍非真实抓取主路径

- 当前来源仍以静态映射为主：[backend/infrastructure/official_source_client.py](backend/infrastructure/official_source_client.py#L14)
- 对“让 LLM 自动查资料后写代码”这个目标来说，资料可信度与覆盖仍不够

### 3.4 执行安全与权限边界不足

要让 LLM 自主改代码，必须新增安全门禁：

- 可修改目录白名单
- 高风险命令拦截
- 关键动作二次确认
- 命令与补丁审计日志

## 4. 推荐的目标架构（LLM 自主实现模式）

建议增加一个面向 LLM 的任务编排层，位于前端与现有服务之间。

### 4.1 角色与职责

1. Planner（计划器）
- 输入：用户需求文本
- 输出：结构化步骤计划（step list + 依赖 + 失败策略）

2. Tool Executor（工具执行器）
- 执行可调用工具：detect、identify、knowledge sync、project generate、code edit、test run
- 每步输出标准化结果与错误码

3. Code Agent（代码代理）
- 根据计划对仓库做受控修改
- 严格限制改动目录
- 生成 patch 与变更说明

4. Verifier（验证器）
- 自动运行测试与关键命令
- 生成 pass/fail 结论与证据

5. Reporter（报告器）
- 输出一次任务的全过程报告
- 包含：做了什么、失败点、修复点、最终结果、下一步建议

### 4.2 建议新增接口

1. 发起任务
- POST /api/v1/agent/jobs
- 入参：requirementText、targetScope、riskLevel、autoApply
- 出参：jobId、status、plan

2. 查询任务
- GET /api/v1/agent/jobs/{jobId}
- 返回：步骤状态、日志、产物、错误码

3. 人工确认节点
- POST /api/v1/agent/jobs/{jobId}/confirm
- 用于高风险动作前确认（如真实烧录、跨目录写入）

4. 变更摘要
- GET /api/v1/agent/jobs/{jobId}/changes
- 返回：文件变更、关键函数变更、测试结果

## 5. 分阶段落地路线

### 阶段 A：接通最小闭环（建议 1-2 周）

目标：先让 LLM 能完成“识别板卡 -> 同步资料 -> 生成工程 -> 跑校验”。

- 新增 jobs 与 job steps 数据模型
- 新增 Agent 编排接口
- 把现有 boards/projects/run-check 服务封装为工具节点
- 前端新增任务进度展示

### 阶段 B：接通代码修改闭环（建议 2-4 周）

目标：让 LLM 可针对需求改仓库代码并自动验证。

- 增加代码编辑工具（限定目录）
- 增加自动测试执行与失败重试
- 增加 patch 审计与回滚点
- 增加“仅建议不落盘”模式与“自动落盘”模式

### 阶段 C：提升可信度与工程可用性（持续）

目标：让结果可用于日常开发。

- 官方资料真实抓取与结构化抽取
- 模板与真实构建链路扩展
- CI 集成与质量门禁
- 指标看板（成功率、自动修复率、平均完成时长）

## 8. 结论

你要的能力方向是可行的，且当前分支已经提供了约 60% 的基础工具能力。真正缺的是“让 LLM 像工程代理一样自主调度这些能力”的编排层与安全闭环。

只要先把编排层和验证闭环补齐，再逐步提升资料抓取与工具链真实度，就可以达到你说的效果：你提需求，LLM 自动查设备、查资料、改代码并回传可审计结果。
