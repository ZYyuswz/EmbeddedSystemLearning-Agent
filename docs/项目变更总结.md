# 项目变更总结

本文档汇总本仓库从**原医疗 RAG 问答系统**改造为**嵌入式系统学习 AGENT**后的主要变更，便于答辩、交接或二次开发时查阅。

---

## 一、定位与目标变化

| 维度 | 原项目 | 当前项目 |
|------|--------|----------|
| 领域 | 医疗问答（疾病 / 药品 / 检查等） | 嵌入式学习（STM32、ESP32、华为开发板、沸腾开发板等） |
| 外部知识 | Neo4j 医疗知识图谱 + Cypher | **本地 JSON**（`data/embedded/embedded_kb.json`）+ **TF-IDF 检索** |
| 大模型 | 曾依赖 Ollama 等 | **通义千问（DashScope OpenAI 兼容）**与 **DeepSeek** HTTP API（`httpx`） |
| 实体识别 | BERT/RoBERTa + 医疗实体词典 | **术语表**（`glossary.txt` + Aho-Corasick），不加载深度学习 NER |

---

## 二、新增与保留的核心文件

### 新增（嵌入式 AGENT 主路径）

| 文件 / 目录 | 作用 |
|-------------|------|
| `embedded_kb.py` | 加载知识库 JSON、字符 n-gram TF-IDF 检索、平台加权、子图与 Mermaid 文本生成 |
| `embedded_glossary.py` | 读取 `data/embedded/glossary.txt`，在查询中匹配术语 |
| `llm_client.py` | 读取 `config/secrets.env`；意图识别（LLM 或规则兜底）；调用通义 / DeepSeek；无 Key 时检索摘要回答 |
| `data/embedded/embedded_kb.json` | 知识点条目（含 `id`、`title`、`tags`、`platform`、`body`、`source`、`related_ids`、`prerequisite_ids`） |
| `data/embedded/glossary.txt` | 嵌入式相关术语，一行一词 |
| `config/secrets.example.env` | API Key 模板；**真实 Key 写在 `config/secrets.env`**（已被 `.gitignore` 忽略） |

### 保留并修改

| 文件 | 变更要点 |
|------|-----------|
| `login.py` | 标题与侧栏改为「嵌入式学习」相关文案；使用 `st.rerun()` |
| `webui.py` | **完全重写**：去掉 Neo4j、`py2neo`、`ollama`、`ner_model`、`torch`；接入上述模块；侧栏平台 / 厂商 / 模型 / 多窗口 / 管理员调试项 |
| `user_data_storage.py` | 逻辑未改，仍管理 `tmp_data/user_credentials.json` |

| `requirements.txt` | 精简为：`httpx`、`numpy`、`pyahocorasick`、`scikit-learn`、`streamlit` |
| `.gitignore` | 增加 `config/secrets.env`、`secrets.env`、`.env`；去掉已无意义的旧模型 / Neo4j 目录规则 |

## 四、功能行为摘要

1. **登录 / 注册** → 进入主界面。  
2. **侧栏**：平台侧重（全部 / STM32 / ESP32 / 华为开发板 / 沸腾开发板）、大模型提供方（通义 / DeepSeek）、模型名、多对话窗口。  
3. **每次提问**：TF-IDF 检索 Top-K 片段 → 意图（有 Key 则 LLM，否则规则）→ 拼装 Prompt → 调用对应 API；失败或无 Key 时输出知识库摘要。  
4. **轻量「知识图谱」加分**：根据条目的 `related_ids` / `prerequisite_ids` 生成小规模 Mermaid 子图，在折叠区展示。
